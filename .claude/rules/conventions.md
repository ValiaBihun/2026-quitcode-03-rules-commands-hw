# Конвенції коду lead-sync

## Контекст

Ядро вже вирішує таймаути, повтори, маскування секретів і валідацію зовнішніх
даних. Код, що обходить ядро, мовчки втрачає ці гарантії — саме так у цьому
проєкті з'являлися нічні інциденти.

**Що з цього перевіряється автоматично, а що ні.** `npm run check:rules` —
порядковий пошук заборонених конструкцій, і він покриває рівно шість пунктів:
`http-via-core` (`fetch`), `env-via-config` (`process.env`), `json-via-parse`
(`JSON.parse`), `log-via-logger` (`console.*`), `no-any`, `no-new-deps` — плюс
`core-untouched` по хешах ядра.

Решту нижче **машина не перевіряє**, їх читає людина на рев'ю: повернення
`Result<T>` замість винятків, контракт `Integration.send()`, заборона мовчазних
дефолтів, мінімізація даних у сповіщеннях, kebab-case та обов'язкові сценарії
тестів. Чистий `check:rules` цих пунктів не підтверджує.

## Правило

- **Помилки — це значення.** Функція, що може не вдатися, повертає `Result<T>` з
  `core/types.ts`. Не кидай винятків назовні: `Integration.send()` **завжди**
  повертає `Promise<Result<void>>`, у тому числі на помилку.
- **HTTP — лише `postJson()`** з `core/http.ts`. Не використовуй `fetch` в
  `integrations/` і `sync/` — у ньому немає таймауту, повторів на 5xx/429 і
  маскування URL у журналі. Не додавай axios, got, ky чи інший HTTP-клієнт.
- **Змінні середовища — лише `readEnv(name)`** з `core/config.ts`. Не читай
  `process.env` поза `core/config.ts`. Значення секрету не пиши в журнал і не
  вшивай у код навіть тимчасово — у журнал іде тільки **ім'я** змінної
  (так само як у полі `requiredEnv`).
- **Зовнішній JSON — лише `parseJson(text, guard)`** з `core/parse.ts`, з guard на
  очікувану форму (складай його з `isRecord`, `isString`, `isNumber`). Не
  використовуй `JSON.parse` напряму. Невалідний JSON чи неочікувана форма — це
  `Result` з `ok: false`, яку видно в журналі. **Не підставляй «значення за
  замовчуванням» мовчки**: так пошкоджені дані стають непомітними.
- **Журнал — лише `log.info` / `log.warn` / `log.error`** з `core/log.ts`. Не
  використовуй `console.*` поза `core/log.ts`: `log` маскує токени, `console.log`
  друкує їх як є.
- **Без `any`** — ні `: any`, ні `as any`, ні `<any>`. Для невідомих даних —
  `unknown` плюс guard. Лід типізуй як `Lead` із `core/types.ts`.
- **Без нових залежностей.** У застосунку нуль runtime-залежностей, і так має
  лишитись. Не запускай `npm install <пакет>`; потрібна бібліотека — спершу
  питання в PR.
- **Мінімізація даних.** У сповіщення (Slack, Telegram, будь-який месенджер) не
  передавай `lead.email` і `lead.phone` — лише `name`, `source`, `budgetUsd`.
  Повні дані йдуть тільки в системи обліку: таблиця, CRM.
- **Імена.** Файли — kebab-case; поле `name` інтеграції збігається з іменем файлу
  без розширення.

## Тести

- Vitest, файл `*.test.ts` поруч із модулем. Реальної мережі в тестах немає:
  `fetch` підміняй через `vi.stubGlobal("fetch", ...)`, змінні — через `vi.stubEnv`.
- Для кожної інтеграції — три випадки: успішна відправка (перевір URL і тіло
  запиту), відсутня змінна середовища, помилка від зовнішньої системи.

### Область дії заборон `console.*` і `JSON.parse`

Обидві заборони стосуються **робочого коду** — того, що виконується в
продакшені. У тестах є рівно два дозволені винятки, і це не послаблення правила,
а опис того, як тести в цьому проєкті вже написані (див. `slack-notify.test.ts`
і `sheets-append.test.ts`):

- **приглушити журнал:** `vi.spyOn(console, "log").mockImplementation(() => {})` —
  щоб вивід `log.*` не засмічував прогін тестів;
- **розібрати перехоплене тіло запиту:** `JSON.parse(String(init?.body))` разом із
  `toEqual` — це перевірка **нашого** запиту, а не довіра до зовнішніх даних.

Чому саме так, а не `expect(init?.body).toBe(JSON.stringify(...))`: порівняння
серіалізованих рядків залежить від порядку ключів, тож тест почне падати від
переставлення полів, яке нічого не змінює. Порівнювати треба структуру.

Тестового винятку для `fetch`, `process.env` і `any` **немає**: мережу підміняй
через `vi.stubGlobal`, змінні — через `vi.stubEnv`, типи бери з `core/types.ts`.

## Як перевірити

- `cd app && npm run check:rules` → нулі в усіх рядках. **Нових** порушень бути
  не повинно: звіряй `TOTAL` до і після своєї зміни, а не з числом у цьому файлі.
- ⚠️ Чистий `check:rules` ≠ код відповідає конвенціям. Перевірка порядкова й
  ловить лише заборонені конструкції. Пункт «не підставляй дефолт мовчки» вона не
  ловить взагалі — приклад живий: `loadState` у `src/sync/state.ts` розбирає JSON
  через `parseJson`, тож формально чистий, але на помилці досі повертає
  `INITIAL_STATE` замість `Result{ok:false}`. Читай сам код, а не лише звіт.
- `cd app && npm test` — зелений; `cd app && npm run typecheck` — без помилок.
- Мінімізація даних: `grep -n "email\|phone" app/src/integrations/slack-notify.ts`
  → порожньо (перевірку для месенджерів роби так само).
