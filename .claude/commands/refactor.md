# Refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Зафіксуй «до»** — виконай і збережи вивід:
   ```bash
   cd app && npm run check:rules && npm test
   ```
   Випиши, скільки порушень саме в цільовому файлі (розділ `by file`).
2. Прочитай цільовий файл, його тест (`*.test.ts` поруч) і ті модулі ядра, на які
   переходиш. Тест — це специфікація поведінки: URL, тіло запиту, тексти помилок.
3. Перепиши файл за `.claude/rules/conventions.md` і `.claude/rules/architecture.md`.
   Типова заміна: `fetch` → `postJson`, `process.env` → `readEnv`, `JSON.parse` →
   `parseJson(text, guard)`, `console.*` → `log.*`, `any` → типи з `core/types.ts`.
4. **Поведінку не змінюй.** Те, що фіксують тести, лишається байт-у-байт: той
   самий URL (включно з query), те саме тіло запиту, ті самі тексти помилок, той
   самий тип експорту (default чи named — як було).
5. **Зафіксуй «після»** — ті самі дві команди. Порівняй з «до».
6. Покажи підсумок: порушення по файлу було → стало, тести було → стало, і
   перелік замін одним рядком кожна.

## Acceptance criteria

- [ ] Порушень `check:rules` у цільовому файлі стало **менше**, у решті файлів —
      не більше, ніж було.
- [ ] `cd app && npm test` зелений і до, і після; **кількість тестів та сама**.
- [ ] `cd app && npm run typecheck` без помилок.
- [ ] Асерти в тестах не редаговані: `git diff -- '*.test.ts'` порожній.
- [ ] Змінено лише цільовий файл: `git status --short` не містить нічого зайвого.

## Stop

Працюй **лише з указаним файлом**. Не «заразом» виправляй сусідні — кожен файл
окремою задачею. Асерти в тестах не редагуй: якщо тест падає, це означає, що
поведінка змінилась — відкоти зміну, а не підганяй тест.

Якщо привести файл до конвенцій не вдається без зміни `app/src/core/**` — діє
`.claude/rules/do-not-touch.md`: зупинись, опиши, що саме потрібно в ядрі, і чекай.
